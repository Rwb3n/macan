## 1. What "decision models" are

The term exists under that name on both OpenRouter and Cloudflare. It names a category of model that **returns probabilities over answers you define, not text**.

**OpenRouter**
- https://openrouter.ai/docs/guides/community/jev (cache), read 2026-10-24:
  - "Jev is a structured decision model from TypeSafe, and the first of its System One models. Send it application state and one or more typed questions, and get back a typed answer with probabilities instead of generated text."
  - "Because the output is typed, code branches on it directly. Jev does not produce reasoning traces, explanations, or free-form text. It is not a drop-in replacement for a chat model. It replaces the prompt-and-parse step where you were asking an LLM a narrow question and extracting a label from its answer."
  - "**Is Jev an LLM?** No. Jev is a System One decision model. It returns typed answers, with probabilities associated with them. Jev doesn't return text, reasoning, or explanations. When you need prose, use a chat model."
  - "As of October 16, 2026, there are 22 decision models from 13 makers, and they all use the same Decisions API" (the blog https://openrouter.ai/blog/insights/what-is-jev/ says "21 decision models from 13 makers" for the same date).
  - Primitives (same page): Choice "Which one of these options?"; Noul "Does this condition hold?" → "The probability of yes"; Score "Where does this fall on an ordered scale?"; Box (Jev only, images).
- https://openrouter.ai/docs/guides/overview/models, read 2026-10-24: "`decisions` | Decision models such as Jev that return typed judgments instead of text."
- https://openrouter.ai/skills/openrouter-decisions, read 2026-10-24: "A decision model reads application state and answers typed questions with probabilities, never text. The model judges, code computes. It is not a chat model, a coding agent, or a replacement for the LLM that drives one."
- Endpoint: "`POST https://openrouter.ai/api/alpha/decisions`" (jev page). It is marked alpha in the path.

**Cloudflare**
- https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/ (changelog dated 2026-10-01), read 2026-10-24: "Clef is a decision model, in the same family as Typesafe's Jev. Instead of generating text, it reads an input state and a set of typed questions, then returns a probability for every allowed answer. Your agent gets a structured decision it can act on immediately, for example: route the ticket, block the request, or escalate to a human."
- https://blog.cloudflare.com/clef-decision-models, read 2026-10-24 (search excerpt): "Jev introduces a new decision model concept into the world of AI — a model that produces bounded structured outputs cheaply, quickly and consistently that can be added into a workflow when a decision is required."

**Maker statement (Microsoft, via its OpenRouter model page)**
- https://openrouter.ai/microsoft/microsoft-decision-1, read 2026-10-24: "Instead of generating text, it reads the provided content and returns a calibrated probability for each fixed answer option ... It is not intended for open-ended generation, conversation, translation, or summarization."

**What this means for R10's job (from the receipts above, not an inference beyond them)**
- **The draft:** the providers say decision models do not produce text ("When you need prose, use a chat model"). They cannot write the request to firms.
- **The pills:** a pill from a fixed set (e.g. survey type) fits `choice`; "is a deadline mentioned?" fits `noul`. Free values (postcode, council, a date) are not a native output.
  - OpenRouter's extraction demo gets them a different way: code finds candidate strings with regexes, and the model picks one or "none". https://openrouter.ai/labs/jev/extract, read 2026-10-24: "Jev picks each field from candidates found in the text, so it cannot invent a value." The code comment reads "One pick-one question per field. The options are the candidates, plus none."
- **A two-model pattern exists:** cheap model drafts, decision model checks. https://openrouter.ai/docs/guides/community/jev: "Cut LLM Cost with a Jev-Verified Cascade drafts with a cheap model, verifies the draft against retrieved context with Jev, and escalates to a stronger model only when the check fails."
  - Whether that is what the principal meant by "claude API + openrouter or cloudflare decision models" is not known (a question for the principal).

## 3. The Jev-Verified Cascade pattern (receipts)

Source: https://openrouter.ai/docs/cookbook/evaluate-and-optimize/jev-verified-cascade (live, read 2026-10-24).

- **What it is:** "A cheap model drafts an answer from your retrieved context, Jev checks whether that context actually supports the draft, and your frontier model rewrites the answer only when the check fails."
- **What it checks:** one `choice` question with three labels:
  - "`supported` means the draft addresses the question and every fact, number, and policy in it appears in the excerpts."
  - "`unsupported` means the draft states something the excerpts don't contain or contradict, or answers a different question."
  - "`declined` means the draft says the excerpts don't cover the question and adds no facts of its own."
- **Threshold:** "The acceptance threshold is `ACCEPT_CONFIDENCE = 0.8`."
- **Stated cost:** "Every tier is paid. The cost per question is your cheap draft plus one Jev check. An escalated question adds a frontier call plus a second Jev check."
- **Stated results** (50 questions, "graded by `~anthropic/claude-opus-latest` against hand-written gold answers"):
  - "the cascade shipped 0 wrong answers at a total of $0.012. Using Astra on every question shipped 2 wrong at $0.175. Luna only shipped 0 wrong at $0.004."
  - "about 7% of the cost".
  - Caveat in the same source: "A difference of 2 answers between runs is attributable to model and judge noise."
- **Stated latency:** none. The page gives no latency figure for the cascade.
- **Models in the recipe:** `~openai/gpt-luna-latest` (draft), `~openai/gpt-astra-latest` (escalation), `typesafe/jev-1.13` (verifier). It is not tied to those models: "Other decision models on OpenRouter ... take the same Decisions API request: change `model` and re-check your thresholds".
- **Constraint:** "throws if the response is a stream, since Jev needs the complete answer text".

## Defects
Clef-flash context conflicts (model page 24,576 vs changelog 64K) and its price differs by route (Workers AI $0.038 vs OpenRouter catalogue `0.000000019`). Clef's OpenRouter FAQ price ($0.042, the cheapest host) differs from the catalogue price (`0.00000024`, Cloudflare). OpenRouter's decision-model count conflicts (22 in the docs vs 21 in the blog, same date; the catalogue API returns 30 entries including aliases and free variants). Haiku and Sonnet latency is relative only. No Gemma 4 latency was found. Liquid's data policy was not found. Perplexity and Upstage EU sentences were not returned. Workers AI processing region is not stated. Two pages came from cache. The Mercury "14 decisions per second" figure comes from a search excerpt of openrouter.ai/models, not a scraped page. The comparator screen did not check which cheaper Workers AI models are also on OpenRouter. The method's Part 2 rule (a schema-valid draft that invents nothing) cannot be met by a decision model alone; this is carried to result.md.
